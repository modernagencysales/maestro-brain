# S10-T01 Lifecycle Adoption Record

**Owner:** S10-T01  
**State:** real local contract

S10-T01 adds the durable `slackIdentityBindings` table and the Slack identity
link Confect contract. Bindings are organization-scoped and store exact
`teamId + slackUserId` metadata for a current WorkOS-backed Maestro user; no
email or display-name field is indexed or accepted as an authorization signal.

## Lifecycle

The binding lifecycle is
`unlinked -> pending_verification -> active -> revoked`. Relinking creates a new
binding generation. Pending intents are nonce-hash bound, short-lived, and
single-use. Slack confirmation must match the expected team and activates only
the exact Slack user id that confirmed the link.

Revocation keeps audit-compatible rows while setting `status=revoked`,
`revokedAt`, and a reason. Connection generation is stored on every binding so
request-time authorization can reject stale Slack workspace generations.

## Compatibility and rollback

The expand migration registers the new table without backfilling existing rows.
Rollback disables Slack answering by treating non-active/current bindings as
unlinked; capture remains unaffected and rows are retained for audit review.

## Focused proof

Focused proof covers the durable index inventory, no email/display-name lookup,
expired/replayed/wrong-team/already-bound failures, exact activation metadata,
and web settings redaction of single-use link tokens.
