# S05-T01 Lifecycle Adoption Record

**Owner:** S05-T01  
**State:** product instance — source ledger schema and migration fragments

## Durable resources

- `providerEventReceipts` stores distinct Slack transport delivery receipts
  under stable tenant-scoped receipt keys. Rows bind organization, connection,
  channel, provider event identity, delivery lane, logical observation key, and
  resulting `sourceRevisionKey` so live/backfill/reconciliation deliveries
  remain auditable while converging on one logical observation.
- `sourceArtifacts` stores one stable source artifact per
  tenant/provider/channel observation identity. The artifact carries the current
  lifecycle state, `latestSourceRevisionKey`, and provider ordering fence
  without exposing Convex IDs as public keys.
- `sourceRevisions` stores immutable content-bearing source revisions with
  normalized text/blocks, schemaVersion `1`, canonical timestamp, permalink,
  author snapshot, provider revision/order metadata, canonical hash, tombstone
  flag, lifecycle envelope, and purge fences for later redaction/retention work.
- `sourceProcessingJobs` stores the initial `assembly_pending` job keyed by a
  stable effect key with tenant, source-unit, revision, status, policy epoch,
  lease, retry, attempt, and effect fencing so source unit assembly can be
  retried idempotently without duplicating ledger writes.

## Lifecycle behavior

- New non-delete source-ledger rows start as `active`. Deletes advance the
  artifact and revision lineage to `deleted_tombstone`; later lifecycle tasks
  may advance content-bearing rows through `redacted` and `purged` without
  deleting the receipt audit trail needed to prove provider delivery history.
- Receipt dedupe is transport-scoped, while observation identity is logical:
  multiple valid receipts may reference the same source revision, but
  conflicting organization/channel/observation bindings are rejected before
  tenant writes.
- Lifecycle generation and stable tenant keys fence every content row. S05-T01
  exposes the artifact-gated readable-current selector contract: readers follow
  `latestSourceRevisionKey` only when the artifact and matching revision
  lifecycle states are active and the revision is not a tombstone. Production
  reader enforcement and derived read revocation remain owned by S05-T03/S07,
  using the same source keys rather than public Convex-ID scans.
- Partial capture failures are transaction-fenced. A failed insert leaves no
  orphan receipt, revision, artifact, or processing job that could later be read
  as captured evidence.

## Compatibility and rollback

- The S05 migration fragment attests `new_tables_only`; no existing table shape
  or canonical integration-owned migration registry output is changed by this
  product lane.
- Historical S00/S01/S02 migration behavior is preserved by extracted task-owned
  implementation modules and strict migration fragments that the integration
  lane assembles deterministically.
- Rollback disables new capture callers and workers, leaving existing source
  ledger rows as exact diagnostic evidence. Do not delete captured rows to
  revert code; re-enable only after the binary understands every stored schema
  version and lifecycle state.
