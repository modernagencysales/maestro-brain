# S08-T03 — Review-First Source Classification

**Owner:** S08-T03

Status: implemented as a fake/local classification seam plus an internal
review-first durable workflow. Classify policies are disabled by default until
eval and UI evidence pass; existing captured source units remain replayable from
their immutable keys and hashes.

## Durable resources

- `classificationDecisions` stores the task-owned proposal and review state for
  one immutable source-unit revision, including source hash, policy generation,
  lifecycle, route, and lease generations, allowlisted target Brain keys,
  evidence quotes, model attempt id, and the eventual reviewed terminal
  decision.
- `sourceProcessingJobs` gains the orthogonal classification stage values needed
  to distinguish execution retry status from durable routing/review state:
  `awaiting_classification`, `classifying`, `awaiting_classification_review`,
  `routed`, `classified_no_route`, `mixed_client_no_route`, `superseded`, and
  `revoked`.
- Direct and capture-only units return a typed zero-call skip result; no durable
  classification decision or model request is created for those policies.

## Lifecycle behavior

Classify policies are the only source-processing policy mode that can assemble a
model request. The request is closed over an immutable source-unit revision key
and hash, message revision keys, policy version, and the finite allowlist of
target Brains. The owning job separately pins lifecycle, route, and lease
generations for commit fencing.

Model output is structural only:

- `single_target` must contain exactly one allowlisted target Brain key.
- `no_target` and `mixed_client` must contain a null target.
- evidence quotes must be present in the immutable source-unit messages.
- confidence and rationale are diagnostic and never authorize a route.

Admin or owner review is required to accept, change an allowed single target,
mark no-route, mark mixed-client/no-route, or reject. V1 intentionally forbids
changing `mixed_client` into a route because no target-safe span splitter
exists. Commit rechecks authority, lifecycle, policy, route, and lease
generations, source hash, and duplicate effects before producing the reviewed
route/no-route result. Reviewer target changes remain inside the request's
pinned allowlist and are valid only for an existing single-target proposal.

The generated internal workflow executes `classification.model`, waits at an
admin approval node, and invokes `routes.commit` once. Its generated control
contract carries the reviewed admin/owner command in the approval event. The
fake/local classifier uses only immutable request text and pinned target display
names; it has no tools, database, Slack, Nango, or provider imports.

## Compatibility and rollback

Rollback disables new classify policies and leaves existing proposals pending.
Do not guess a Brain fallback. Pending proposals can be replayed from
source-unit key/hash, policy version, lifecycle generation, and the stored
finite allowlist. The fake/local seam has no Slack, Nango, database adapter, or
tool imports, preserving deterministic replay and provider isolation.
